# Bài 8.2 — Phân tích lưu lượng điều khiển LED ESP32-S3 qua Wi-Fi bằng Wireshark

## 1. Mục tiêu

Điều khiển LED onboard trên ESP32-S3 chạy ESPHome và sử dụng Wireshark để tìm hiểu địa chỉ IP, kết nối TCP, yêu cầu HTTP và dữ liệu trạng thái thiết bị.

Báo cáo được điều chỉnh theo cấu hình YAML và địa chỉ IP sinh viên cung cấp. Chưa có bản bắt gói của hệ thống này nên các nội dung dưới đây là mô tả cấu hình, hướng dẫn quan sát và cách phân tích; không phải số liệu thực nghiệm đã xác nhận.

## 2. Thiết bị và địa chỉ mạng

| Thành phần | Thông tin |
|---|---|
| Sinh viên | Nguyễn Minh Tuấn |
| Board | ESP32-S3 DevKitC-1 (Espressif) |
| Tên thiết bị ESPHome | `minhtuan` |
| Home Assistant | `172.20.10.5` |
| ESP32-S3 điều khiển LED | `172.20.10.4` |
| LED | WS2812, 1 LED, GPIO48, thứ tự màu GRB |
| Web server của ESP | HTTP, TCP cổng 80 |
| ESPHome Native API | TCP cổng mặc định 6053, bật mã hóa |

Địa chỉ `172.20.10.4` thuộc ESP32-S3; LED onboard không có địa chỉ IP riêng. YAML chưa khai báo IP tĩnh nên cần kiểm tra lại địa chỉ sau khi thiết bị kết nối lại mạng.

## 3. Nguyên lý hoạt động theo cấu hình

ESP32-S3 kết nối mạng Wi-Fi. Khi khởi động đến bước `on_boot`, thiết bị bật LED với hiệu ứng `Blink Fast`: sáng màu xanh lá 500 ms rồi tắt 500 ms. Chu kỳ nhấp nháy khoảng 1 giây được thực hiện ngay trên ESP.

Vì vậy, LED tự nhấp nháy sau khi khởi động không chứng minh Home Assistant đang gửi lệnh liên tục.

Cấu hình hỗ trợ hai đường điều khiển:

| Cách thao tác | Đường giao tiếp | Nội dung quan sát |
|---|---|---|
| Mở trang web ESP tại `http://172.20.10.4` | Trình duyệt ↔ ESP, TCP 80 | GET, POST, phản hồi HTTP và sự kiện SSE |
| Điều khiển qua tích hợp ESPHome trong Home Assistant | HA `172.20.10.5` ↔ ESP `172.20.10.4`, TCP 6053 | Kết nối TCP và dữ liệu Native API mã hóa |

Nếu mở web ESP bằng trình duyệt trên máy tính, IP nguồn của yêu cầu là IP máy tính đó. Không tự gán IP máy tính thành IP Home Assistant. Việc khai báo `web_server: port: 80` không làm tích hợp ESPHome chuyển sang điều khiển bằng HTTP.

## 4. Các lớp giao thức

| Lớp | Giao thức hoặc thành phần | Vai trò |
|---|---|---|
| Liên kết mạng | Wi-Fi | Kết nối ESP vào mạng không dây |
| Mạng | IPv4 | Định địa chỉ và chuyển gói giữa các thiết bị |
| Giao vận | TCP | Thiết lập kết nối, truyền và xác nhận dữ liệu |
| Ứng dụng | HTTP/SSE hoặc ESPHome Native API | Điều khiển LED, trao đổi trạng thái |

Nếu bắt trên giao diện mạng thông thường, Wireshark có thể trình bày khung dạng Ethernet dù ESP kết nối bằng Wi-Fi. Bản bắt như vậy phục vụ phân tích IP/TCP/ứng dụng; không đủ để phân tích kênh, RSSI hoặc khung quản lý Wi-Fi.

## 5. Bộ lọc Wireshark

### 5.1. Toàn bộ lưu lượng IP của ESP

```wireshark
ip.addr == 172.20.10.4
```

### 5.2. HTTP của web server ESP

```wireshark
ip.addr == 172.20.10.4 && tcp.port == 80
```

Tìm yêu cầu tải trang hoặc lấy dữ liệu:

```wireshark
ip.addr == 172.20.10.4 && http.request.method == "GET"
```

Tìm yêu cầu điều khiển:

```wireshark
ip.addr == 172.20.10.4 && http.request.method == "POST"
```

### 5.3. Native API giữa Home Assistant và ESP

```wireshark
ip.addr == 172.20.10.5 && ip.addr == 172.20.10.4 && tcp.port == 6053
```

Bộ lọc này giữ gói giữa hai IP theo cả hai chiều. Do cấu hình có `api.encryption`, dữ liệu ứng dụng không hiển thị thành lệnh HTTP hoặc văn bản rõ.

## 6. Quy trình thực hành với HTTP cổng 80

1. Cho máy tính và ESP kết nối mạng có thể liên lạc với nhau.
2. Mở Wireshark, chọn giao diện mạng đang sử dụng và bắt đầu bắt gói.
3. Áp dụng bộ lọc `ip.addr == 172.20.10.4 && tcp.port == 80`.
4. Mở hoặc tải lại trang `http://172.20.10.4` để thu được yêu cầu từ đầu phiên.
5. Thao tác tắt LED, sau đó bật LED; ghi lại thời điểm và quan sát LED thực tế. Nếu muốn LED sáng liên tục, chọn hiệu ứng None trên giao diện nếu có.
6. Tìm yêu cầu POST, mở phần Hypertext Transfer Protocol và đọc Request Method, Request URI, địa chỉ nguồn/đích.
7. Đọc phản hồi HTTP và thông báo trạng thái. Nhấp phải gói → Follow → TCP Stream để xem toàn bộ nội dung trao đổi.

Nếu chỉ nhìn thấy TCP, cần kiểm tra việc bắt từ đầu kết nối và khả năng tái lắp ghép HTTP. Một số đoạn thuộc luồng sự kiện đang mở có thể chỉ được gắn nhãn TCP.

## 7. Phân tích các loại gói

### 7.1. Bắt tay TCP ba bước

| Bước | Chiều đối với phiên web | Ý nghĩa |
|---|---|---|
| SYN | Máy tính → ESP `172.20.10.4:80` | Yêu cầu thiết lập kết nối |
| SYN, ACK | ESP → máy tính | Chấp nhận và xác nhận yêu cầu |
| ACK | Máy tính → ESP | Hoàn tất bắt tay |

Cổng phía máy tính thường là cổng tạm thời và phải đọc từ bản bắt thực tế; không mặc định bằng 80.

### 7.2. HTTP GET

GET được dùng để yêu cầu trang web hoặc dữ liệu từ ESP. Ví dụ minh họa:

```http
GET / HTTP/1.1
Host: 172.20.10.4
```

ESPHome cũng cung cấp luồng sự kiện tại `/events`. Luồng này giúp trình duyệt nhận cập nhật từ thiết bị. Cần đọc URI thực tế để xác định mục đích từng GET.

### 7.3. HTTP POST điều khiển LED

LED trong YAML thuộc domain `light` và có tên `minhtuan`. Đường dẫn dự kiến, cần đối chiếu định danh thực tế trên thiết bị:

```http
POST /light/minhtuan/turn_on HTTP/1.1
Host: 172.20.10.4
```

```http
POST /light/minhtuan/turn_off HTTP/1.1
Host: 172.20.10.4
```

`status_led` là ID nội bộ trong YAML, không tự động được dùng làm định danh trong URI HTTP. URI và tham số phải được xác nhận bằng gói bắt thực tế hoặc thông tin thực thể của web API.

Để kết luận thao tác thành công, cần đối chiếu yêu cầu, phản hồi, trạng thái được báo và LED thực tế. TCP ACK chỉ xác nhận nhận dữ liệu, không chứng minh LED đã bật hoặc tắt.

### 7.4. Sự kiện SSE: ping và state

Web server ESPHome sử dụng Server-Sent Events (SSE). `event: ping` giúp duy trì luồng sự kiện; `event: state` mang cập nhật trạng thái thực thể.

`event: ping` không phải lệnh bật LED, không phải TCP Keep-Alive và cũng không phải ICMP Echo của lệnh ping trên máy tính.

### 7.5. Các trường TCP cần đọc

| Trường | Ý nghĩa |
|---|---|
| Source / Destination | IP nguồn và IP đích |
| Source Port / Destination Port | Cổng của hai đầu kết nối |
| Sequence Number | Số thứ tự byte trong luồng TCP |
| Acknowledgment Number | Số thứ tự byte tiếp theo phía nhận mong đợi |
| TCP Segment Len | Số byte dữ liệu trong đoạn TCP |
| SYN / ACK / PSH / FIN | Cờ thiết lập, xác nhận, đẩy dữ liệu và đóng chiều gửi |
| TCP Stream | Chỉ số dùng để phân biệt từng kết nối |

Các gói cùng IP nhưng khác cổng tạm thời có thể thuộc các kết nối khác nhau. Không dùng số thứ tự gói, Seq/Ack, độ dài hoặc chỉ số stream của file mẫu làm kết quả bài này.

### 7.6. Nếu xuất hiện M-SEARCH

M-SEARCH thuộc SSDP, thường dùng UDP cổng 1900 để tìm dịch vụ trong mạng. Đây không phải yêu cầu HTTP điều khiển LED gửi tới ESP cổng 80. Chỉ phân tích mục này nếu bản bắt thực tế có gói tương ứng.

## 8. Kiểm tra điều khiển từ Home Assistant

Nếu sử dụng tích hợp ESPHome, bắt lưu lượng tại Home Assistant hoặc vị trí mạng có thể quan sát trao đổi giữa `172.20.10.5` và `172.20.10.4`, rồi lọc TCP cổng 6053. Thao tác bật/tắt thực thể LED và đối chiếu thời điểm với dữ liệu truyền.

Máy tính khác cùng Wi-Fi không nhất thiết nhìn thấy lưu lượng unicast HA ↔ ESP. Khi chỉ bắt trên máy tính đó, không thấy gói chưa đủ để kết luận Home Assistant không gửi lệnh.

## 9. Kết luận

Hệ thống của Nguyễn Minh Tuấn sử dụng ESP32-S3 có tên `minhtuan`, địa chỉ `172.20.10.4`, điều khiển LED WS2812 onboard tại GPIO48. Home Assistant có địa chỉ `172.20.10.5`. ESP hỗ trợ web HTTP tại cổng 80 và ESPHome Native API mã hóa tại cổng mặc định 6053. Qua Wireshark, có thể phân tích kết nối TCP, yêu cầu GET/POST và sự kiện SSE khi thao tác trên web ESP; với tích hợp ESPHome, cần theo dõi cổng 6053. Hiệu ứng nhấp nháy khi khởi động chạy cục bộ trên ESP. Cần bổ sung ảnh hoặc bản bắt gói của hệ thống để xác nhận các lệnh và thông số thực nghiệm.
